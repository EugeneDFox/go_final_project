# Планировщик задач (Task Scheduler)

Веб-приложение для управления задачами с поддержкой повторяющихся событий, поиска и фильтрации. Серверная часть написана на Go, использует SQLite для хранения данных и предоставляет REST API. Фронтенд — одностраничное приложение на HTML/CSS/JavaScript.

## Описание проекта

Проект создан для демонстрации построения полнофункционального веб-сервера на Go с использованием современных практик: работа с переменными окружения, повторяющиеся задачи по сложным правилам, полнотекстовый поиск, аутентификация через JWT, статический фронтенд и контейнеризация через Docker.

Основные возможности:
- Создание, редактирование, удаление задач
- Задачи могут быть разовыми или повторяющимися по дням недели, дням месяца с указанием месяцев
- Автоматический расчёт следующей даты при выполнении повторяющейся задачи
- Поиск задач по тексту (заголовок, комментарий) или по конкретной дате
- Защита API токеном (JWT), если задан пароль через переменную окружения
- Готовый Docker‑образ для быстрого развёртывания

## Список выполненных заданий со звёздочкой

1. **Реализована возможность определять извне порт при запуске сервера.**  
   Если существует переменная окружения `TODO_PORT`, сервер при старте слушает порт со значением этой переменной. Иначе используется порт по умолчанию (`7540`).

2. **Реализована возможность определять путь к файлу базы данных через переменную окружения.**  
   Сервер читает значение переменной `TODO_DBFILE` и использует его в качестве пути к SQLite‑базе. Если переменная не задана, используется `scheduler.db` в текущей директории.

3. **Поддержка правил повторения задач:**
   - `w <через запятую от 1 до 7>` — задача назначается в указанные дни недели, где 1 — понедельник, 7 — воскресенье.
   - `m <через запятую от 1 до 31, -1, -2> [через запятую от 1 до 12]` — задача назначается в указанные дни месяца. Вторая последовательность чисел опциональна и указывает на определённые месяцы.

4. **Добавлена возможность выбирать задачи через строку поиска.**  
   Обработчик `/api/tasks` принимает параметр `search` в строке запроса. Если переданная строка соответствует формату `02.01.2006`, возвращаются задачи на эту дату. Иначе выполняется поиск подстроки в заголовке или комментарии задачи (регистронезависимый).  
   Пример: `/api/tasks?search=бассейн` вернёт задачи со словом «бассейн».

5. **Создан Docker‑образ с веб‑сервером.**  
   Многоступенчатый `Dockerfile` собирает статический бинарник Go и копирует фронтенд. Образ опубликован на Docker Hub (или может быть собран локально).

## Инструкция по запуску кода локально

### Предварительные требования
- Установленный Go 1.25 или новее
- Современный браузер

### Шаги
1. Клонируйте репозиторий и перейдите в его корень:
   ```bash
   cd go_final_project
   ```

2. Установите зависимости:
   ```bash
   go mod download
   ```

3. Создайте файл `.env` в корне проекта (опционально, для переопределения настроек):
   ```env
   TODO_PORT=7540
   TODO_DBFILE=scheduler.db
   TODO_PASSWORD=12345
   ```
   - `TODO_PORT` — порт, на котором будет работать сервер.
   - `TODO_DBFILE` — путь к файлу базы данных SQLite.
   - `TODO_PASSWORD` — пароль для генерации JWT‑токена. Если не задан, аутентификация отключена.

4. Запустите сервер:
   ```bash
   go run main.go
   ```
   Или соберите и запустите бинарник:
   ```bash
   go build -o server_app .
   ./server_app
   ```

5. Откройте в браузере адрес:  
   **http://localhost:7540** (или другой порт, если вы изменили `TODO_PORT`).

   Фронтенд будет загружен автоматически. Если задан `TODO_PASSWORD`, потребуется ввести его на странице входа.

## Инструкция по запуску тестов

В директории `tests/` находятся интеграционные тесты, проверяющие корректность работы API.

### Настройка тестов
Параметры тестов задаются в файле `tests/settings.go`:
```go
var Port = 7540            // порт, на котором запущен сервер
var DBFile = "../scheduler.db" // путь к файлу базы данных (относительно tests/)
var FullNextDate = true    // включить тесты полной функциональности NextDate
var Search = true          // включить тесты поиска
var Token = `...`          // JWT‑токен для аутентификации (генерируется автоматически)
```

**Примечания:**
- Для тестирования поиска убедитесь, что переменная `Search` в `tests/settings.go` установлена в `true`.
- Для полной проверки правил повторения (недели, месяцы) установите `FullNextDate = true`.
- Токен аутентификации (`Token`) уже настроен для пароля `12345`. Если вы изменили пароль, обновите токен, взяв его из ответа `/api/signin`.

### Запуск тестов

 Выполните в корне проекта одну из команд:

   - Для запуска всех тестов:
     ```bash
     go test ./tests/...
     ```

   - Для запуска конкретного теста используйте `-run` с именем тестовой функции:
     ```bash
     go test -run ^TestApp$ ./tests        # тестирование сервера
     go test -run ^TestDB$ ./tests         # тестирование базы данных
     go test -run ^TestNextDate$ ./tests   # тестирование функции NextDate() и обработчика /api/nextdate
     go test -run ^TestAddTask$ ./tests    # тестирование добавления задачи
     go test -run ^TestTasks$ ./tests      # тестирование получения списка задач (и поиска, если Search=true)
     go test -run ^TestTask$ ./tests       # тестирование редактирования задачи
     go test -run ^TestEditTask$ ./tests   # тестирование обновления параметров задачи
     go test -run ^TestDone$ ./tests       # тестирование отметки о выполнении задачи
     go test -run ^TestDelTask$ ./tests    # тестирование удаления задачи
     ```

   - Для запуска отдельного тестового файла:
     ```bash
     go test -v ./tests/task_6_test.go
     ```

## Инструкция по сборке и запуску проекта через Docker

### Сборка образа
Из корня проекта выполните:
```bash
docker build -t task-scheduler:latest .
```

### Запуск контейнера
```bash
docker run -p 7540:7540 \
  -v $(pwd)/data:/data \
  -e TODO_PORT=7540 \
  -e TODO_DBFILE=/data/scheduler.db \
  -e TODO_PASSWORD=12345 \
  task-scheduler:latest
```

**Пояснение параметров:**
- `-p 7540:7540` — проброс порта (гостевой порт :7540).
- `-v $(pwd)/data:/data` — монтирование директории `data` для сохранения базы данных на хосте.
- Переменные окружения можно опустить — в образе уже заданы значения по умолчанию.

После запуска откройте браузер по адресу **http://localhost:7540**.
